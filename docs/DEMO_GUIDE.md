# NexusResearch-AI — recruiter demo runbook

> **Status:** Recording and screenshot instructions only. No screenshots or benchmark results are supplied in this repository yet.

## Prepare

1. Read [README.md](../README.md); install dependencies from `requirements.txt`.
2. Provide `GROQ_API_KEY` and `TAVILY_API_KEY` locally via an untracked `.env` file or suitable environment variables.
3. Run `streamlit run app.py`. A network connection and API access are required.
4. Choose a bounded example such as `Explain retrieval-augmented generation and its trade-offs`. Real search results will vary.

## 60-second storyboard

| Seconds | Show | Say |
| --- | --- | --- |
| 0–10 | Topic input and four-stage board | “This project chains specialized steps rather than sending one giant prompt.” |
| 10–25 | Click Run Research Pipeline and show Search → Read stages | “Search queries Tavily; the reader chooses and extracts material from a source.” |
| 25–36 | Writer → Critic stages complete | “The writer synthesizes a report, then a critic model provides feedback.” |
| 36–47 | Report tab, including source URLs if present | “I keep the source references visible, but generated claims still require verification.” |
| 47–54 | Critic Feedback tab | “The feedback is generated by an LLM; it is not independent fact-checking.” |
| 54–60 | History or Download Report | “A research run can be revisited and the draft report downloaded.” |

**Practical recording tip:** The pipeline depends on live network calls and may take longer than one minute. Record a full working run, then *edit* the recording to a concise walkthrough; do not falsify outputs.

## Interview questions

**What makes this a multi-stage AI application?** A search agent, reader agent, writer chain and critic chain each have a defined role, with intermediate state passed to the next stage.

**How do you control hallucinations?** Currently the project asks models to use search results, but the critique is another model output; it does **not** establish factual correctness. Source validation and evaluation are future work.

**Where can this fail?** Search quotas, blocked scraping, missing API keys, unreliable sources, long prompts and LLM-generated inaccuracies.

**How would you improve it?** Add citation-grounding checks, structured output validation, per-stage retry/timeout handling and tests with fixed search fixtures.
